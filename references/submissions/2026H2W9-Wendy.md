## 三、遇到的真实阻塞及处理方式

### 阻塞 1 · 课程正文提取为空（主阻塞）

16 篇全部失败，统一报错：

```
saved note has no extracted article content
```

即：笔记被创建了，但正文抓不到，落库为空壳。

**定位过程（三步排除法）：**

| 排查项 | 结论 |
| --- | --- |
| 账号额度 | 充足，`write_note` 34/1000，排除额度限制 |
| 权限 / 授权 | `Authenticated`，排除鉴权失败 |
| 抓取管线本身 | 用确定可访问的公开页做阳性对照，**抓到了完整标题 + 正文 + 标签**，管线正常 |

三条排除后只剩一个可能：得到课程正文需要**登录态 + 已购权限**才能读到，而得到大脑是服务端抓取，**拿不到我浏览器里的得到登录 Cookie**，请求落到未登录状态，被付费墙拦在门外。

**定性**：付费 / 登录墙导致的权限受限，**不是工具故障，也不是操作失误**。

**处理方式**：按协议第 6 条——遇到权限受限**立即停止，不重复提交、不绕过**。我没有再跑第二轮批量，也没有尝试任何绕过付费墙的办法。

**留下的待清理项**：本轮在得到大脑中产生了 18 条空壳笔记 + 2 条对照测试笔记，需清理（本文完成时尚未清理，删除属不可逆操作，已单独与用户确认后再执行）。

## 五、对「Skill 串联」的理解

这周最大的收获不是导进了多少篇，而是第一次把**四种能力拆开、各司其职**地串成一条链：

| 环节 | 负责什么 | 保存物 |
| --- | --- | --- |
| 浏览器 | 发现课程自身 + 已发布正文 URL | URL 清单 |
| 本地清单 | 按 ID / URL 去重、预检 | 清单 + 状态文件 |
| 得到大脑 | 提取全文 | 笔记 |

之前我会把这三件事混在一起做，结果就是：一旦某个环节失败，根本说不清是**发现漏了**、**去重错了**，还是**提取被拦了**。

这次 16 篇全军覆没，但正因为链路是拆开的，我才能在 20 分钟内把问题精确定位到「提取环节被付费墙拦」——而不是笼统地归咎于「工具不好用」或「我操作有问题」。**链路拆得越清晰，失败越有诊断价值。**

另一个体会：**「跑通流程」和「任务成功」是两件事**。本周流程确实跑通了（5 步全部执行、每步都有可核验的产出物），但任务目标（课程正文进库）没达成。按题面要求以最终同步状态判定，我如实记为**未达成**，不拿「命令都跑完了」当完成。

## 六、下次可复用的一条规则

> **批量动作之前，先用一个「确定能成功」的最小样本做阳性对照，再决定要不要全量跑。**

这条规则本周救了我两次：

1. **导入前先试 1 篇**——如果没试就直接全量跑 4 门课 39 篇，只会得到 39 条空壳笔记和一堆无法定位的噪音，清理成本翻倍。
2. **失败后先用公开页做对照**——如果没有这一步，我大概率会把「付费墙」误判成「工具坏了」，然后去折腾工具、重复提交，既浪费额度又污染笔记库。

**规则要点**：对照样本必须选**结果确定已知**的（我第一次拿了个 404 页面做对照，结论无效，白跑一趟）。对照成立 → 问题在目标侧；对照失败 → 问题在工具侧。一次对照胜过十次盲重试。
